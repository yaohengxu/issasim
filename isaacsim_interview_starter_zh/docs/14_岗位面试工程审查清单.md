# 站在面试官角度的工程审查清单

## 1. 面试官真正要确认什么

```text
会启动 demo？           基础门槛
能解释每层原理？        技术理解
能定位不稳定问题？      工程能力
能定义评估和边界？      结果意识
能迁移/协作/维护？      岗位匹配
```

具身仿真岗位不只考“会不会调用 API”。面试官通常通过一个抓取例子追问：资产是否可信、坐标如何统一、动作在哪执行、为何成功、失败怎么复现、怎样接真机。

## 3. 一个 3 分钟项目陈述模板

```text
0:00 任务：在桌面场景将目标物放入容器；成功定义是……
0:25 场景：USD 分成机器人/环境/任务层；物理参数来自……
0:55 感知：输入是……，坐标通过……对齐；仿真真值只用于……
1:25 控制：策略输出……，经……转换为关节目标；控制/物理频率为……
1:55 验证：固定 seed smoke + N 个随机 episode；指标是……
2:25 失败：曾出现……，通过检查……定位，改为……，结果……
2:50 边界：当前仍未覆盖……；下一步用……验证 Sim-to-Real。
```

没有真实项目时，基于本工程演示也要如实说“这是最小闭环”。可以提出下一步实验，但不要伪造真机成功率或物理保真度。

## 4. 深挖问题与回答骨架

### Q：仿真中成功率 95%，为什么真机失败？

按“感知、几何/标定、动力学、执行延迟、安全约束”分解，不猜单一原因。对比真机日志与仿真 state distribution，先复现高频失败，再校准和随机化；必要时改变 action space 或加入闭环视觉/力反馈。

### Q：你如何证明不是 controller 利用了仿真漏洞？

检查 action 是否越过限位/速度/力限制，是否有 teleport、穿透、非真实约束；随机化物理和观测；在未见资产/pose 上评估；将动作回放并检验接触和成功的持续性。

### Q：一段代码跑得慢，先看哪里？

用 profiler 分开测资产载入、渲染、物理、Python 与数据落盘。训练时先关不需要的 render/annotator，减少每帧 USD 查找，做 batch 化；不要在无数据前优化算法。

### Q：USD 改动如何不破坏控制代码？

稳定的 prim path/配置映射是接口；用 scene manifest 和载入时校验（articulation root、dof name、sensor path）。资产基础层不可随任务直接修改，任务用 override 或配置表达差异。

## 5. 红旗回答

- “Isaac Sim 会自动把模型变成物理物体。”
- “有画面就说明碰撞和抓取正确。”
- “随机化越大，Sim-to-Real 越好。”
- “controller done 就等于任务成功。”
- “能跑 GUI 就等于工程可复现。”
- “IK 有解，所以路径一定无碰。”

把这些说法改为有条件、可验证的工程表达，会显著提升可信度。

## 6. 面试前最后材料

准备一页纸即可：架构 ASCII 图、一个 USD 树、一个控制循环、三个关键参数、三个指标、一个失败案例、一个已知限制。带上可运行命令和短录屏，但随时能脱离 PPT 把系统画出来。

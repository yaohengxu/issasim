# 场景、物理与 USD 实操

## 建一个可信任务场景的顺序

1. 新建 Stage，确定单位和 up axis；本项目按米。
2. 加地面、桌子、灯光和相机。
3. 引用机器人 USD，选定 variant，检查基座 pose。
4. 给可交互物体添加 visual、collider、rigid body、物理材质。
5. `reset` 后再读写 articulation 状态。
6. 让物体先静置若干帧，确认没有初始穿透和飞散。
7. 记录随机种子、配置与成功指标，保证实验可复现。

## 碰撞与材质

摩擦不是“让物体不滑”的万能参数。抓取是否稳定还受法向力、夹爪形状、接触求解器、物体质量、控制延迟影响。恢复系数决定碰撞弹性；桌面和物体过高的 restitution 常导致跳动。

建议从合理物理范围开始随机化，而非极端随机：

```text
质量  : 标称值 × [0.8, 1.2]
摩擦  : [0.4, 1.0]（按材料再收窄）
物体位姿: xy 小范围、yaw 0~360°
相机  : 位姿小扰动、曝光/噪声/光照变化
执行器: action delay、关节噪声、速度/力矩限制
```

## Reset 语义

`reset()` 不只是把画面清空：它会初始化物理状态和部分包装器。要为每个 episode 明确设置机器人默认关节角、物体初始 pose、随机化参数和任务状态机；不要让上一回合的速度、约束或 controller 内部状态泄漏到下一回合。

## 什么时候不该直接改 pose

直接设置动态刚体 pose 等价于 teleport，适合 reset 或数据布置；在执行过程中持续 teleport 会绕开接触动力学。要模拟真实交互，应让控制器驱动机器人，交给 PhysX 处理碰撞；为做 task-level 抽象而使用固定约束时，应明确说明这不是纯接触抓取。

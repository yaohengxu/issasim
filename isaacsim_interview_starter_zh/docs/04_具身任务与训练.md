# 具身任务、合成数据与 Sim-to-Real

## 任务应明确写成 MDP

- **Observation**：关节位置/速度、末端 pose、RGB-D、分割、物体 pose、上一动作等。
- **Action**：关节目标、关节增量、末端 delta pose 或夹爪开合。
- **Transition**：物理仿真和传感器渲染。
- **Reward**：接近、抓住、抬升、放置、成功；同时惩罚碰撞、超限、过大动作。
- **Termination**：成功、掉落、碰撞、超时。

奖励应服务于最终任务，避免 reward hacking。以抓放为例，单纯奖励“末端离物体近”会让策略停在物体旁；应加入阶段性稀疏成功奖励和安全约束。

## 合成数据

Isaac Sim 可用随机化的资产、材质、灯光、相机和背景生成 RGB、深度、语义/实例分割、2D/3D 框、姿态等标注。核心价值是低成本覆盖长尾场景；关键风险是渲染、资产和噪声与真实世界不一致。

评价数据而不是只评价图片：检查类别平衡、遮挡、边界、尺度、相机内参、标注坐标系及其在真实验证集上的效果。

## Sim-to-Real 的务实流程

1. 标定机器人运动学、相机内外参、桌面和夹爪几何。
2. 用现实测量值设置质量、摩擦、控制频率、限位和延迟。
3. 进行 domain randomization，提高策略对不确定性的鲁棒性。
4. 先在 shadow mode / 低速 / 安全限位下验证，再逐步扩大工作空间。
5. 用真实失败样本反向更新随机化范围和资产库。

**随机化不是越大越好**：范围脱离现实会让训练难度无意义上升，或学到保守策略。它应基于估计误差与真实分布。

## Isaac Sim、Isaac Lab、ROS 2 的分工

- Isaac Sim：场景、物理、渲染、传感器、资产和交互。
- Isaac Lab：面向机器人学习的任务、并行环境、训练工作流（具体 API 随版本变化）。
- ROS 2：与真实机器人或外部模块通信；它不是物理引擎。

# 传感器、坐标变换与合成数据

## 1. 控制器看到的不是“世界真值”

```text
           物理世界状态（sim ground truth）
                  │
      ┌───────────┼──────────────────┐
      ▼           ▼                  ▼
关节编码器      相机 RGB-D          接触/力信息
      │           │                  │
   noise/delay  rendering + noise   filtering/threshold
      └───────────┴──────────────────┘
                  ▼
          observation vector / dict
                  ▼
            controller / policy
```

训练或调试可以读 ground truth；部署到真机的策略不能依赖仿真中不存在的 object pose、完美分割图或零延迟接触力。工程上应明确每个 observation 的来源、频率、延迟、噪声模型和是否允许真机使用。

## 2. 相机模型：内参、外参和像素投影

```text
P_world -- T_camera_world --> P_camera = (Xc, Yc, Zc)
                              │
                              └─ K --> [u, v, 1]^T

u = fx * Xc/Zc + cx
v = fy * Yc/Zc + cy
```

- **内参 K**：焦距 `fx, fy`、主点 `cx, cy`，以及畸变模型。
- **外参**：相机相对于世界/机器人基座的刚体变换。务必说明矩阵的方向，例如 `T_camera_world` 还是 `T_world_camera`。
- **Depth**：先确认是 z-depth、ray distance，还是特定渲染产品定义；单位和无效值也要确认。

相机标定错误往往表现为“检测框看起来对，但机械臂永远抓偏”。排查必须把同一个 3D 点依次画在世界、相机和像素坐标中，而不只是改 IK。

## 3. 常见传感器与适用任务

| 传感器/数据 | 典型用途 | 关键工程问题 |
| --- | --- | --- |
| RGB | 检测、分割、VLA | 光照、曝光、材质域差 |
| Depth / RGB-D | 6D pose、避障、抓取 | 噪声、孔洞、深度定义、外参 |
| 语义/实例分割 | 合成数据、监督训练 | 类别表、实例 ID、遮挡 |
| 2D/3D box、keypoint | 检测与姿态监督 | 坐标系、遮挡截断、标注规范 |
| IMU / lidar | 移动机器人 | 频率、漂移、运动畸变 |
| joint/contact/force | 低层控制、抓取判定 | 采样频率、滤波、真机可得性 |

## 4. 合成数据流水线

```text
资产库 + 类别/实例语义
         │
         ▼
场景采样：对象、相机、灯光、材质、背景
         │
         ▼
渲染产品：RGB / depth / segmentation / bbox / pose
         │
         ▼
标注转换与质量检查 → 数据集版本 → 训练/验证
```

Replicator 类工具的核心不只是“随机好看的背景”，而是把**随机化的变量、范围、种子、标注定义、输出格式**作为可复现实验的一部分。建议为每个样本记录：scene id、资产版本、相机内参/pose、随机化参数、渲染引擎配置和 annotation schema 版本。

## 5. Domain randomization 的层次

```text
几何层：尺寸、形状、摆放、遮挡
外观层：纹理、反射、光源、背景、曝光
传感层：噪声、模糊、深度孔洞、时间戳延迟
动力学层：质量、摩擦、阻尼、关节 drive
执行层：动作延迟、控制频率、关节误差
```

随机化区间要由真实误差或任务需求支撑。范围太窄会过拟合仿真；范围太宽会把大量算力花在不可能世界并使策略变得保守。应该以真实验证集或真机成功率做消融：只加光照、再加相机、再加摩擦，量化收益。

## 6. 数据质量审查

不要只抽看几张漂亮图片，应自动检查：

- 各类别、尺度、距离、遮挡率是否平衡；
- bbox 是否越界、分割是否漏标，实例是否唯一；
- pose 的轴定义、单位、四元数顺序是否有统一约定；
- RGB、depth、mask 是否来自同一相机时间点；
- 训练/验证/测试是否在资产实例、场景与 seed 上泄漏；
- 少量真实帧上的视觉统计或下游指标是否改善。

## 7. 面试可讲案例

“如果要做杯子抓取感知，我会先冻结相机坐标约定和类别 schema，用已知 3D marker 做 world→camera→pixel 的单元测试；再用资产、摆放、遮挡、光照和材质做可追溯随机化，导出 RGB-D、实例分割和 6D pose。最终不是只看合成标注，而是用真实桌面帧验证 detection/pose 误差，并把失败场景反馈到资产和随机化范围。”

# 控制代码如何接入 Isaac Sim

## 1. 先定义稳定的控制接口

控制器不应直接依赖某个 Prim 路径散落在算法内部。将仿真包装成适配层：

```text
Task / Env
  ├─ reset(seed) -> observation, info
  └─ step(action) -> observation, reward, terminated, truncated, info
          │
          ▼
SimulatorAdapter
  ├─ read_robot_state() / read_sensors() / read_contacts()
  ├─ apply_joint_position_targets(q_target)
  ├─ apply_joint_efforts(tau)
  ├─ step_physics(n) / render()
  └─ reset_scene(task_config)
          │
          ▼
Isaac Sim Stage + Articulation + Sensors + PhysX
```

这样 controller、planner、RL policy 和 ROS client 都只面对明确的 `observation/action` 协议；从 Franka 换成别的机械臂时主要改 adapter 和配置，不重写算法。

## 2. 控制循环的正确时序

```text
episode reset
  ├─ 采样 task config / randomization
  ├─ 设置物体初始状态（允许 teleport）
  ├─ reset physics + controller internal state
  └─ 等待若干帧稳定

每个控制周期
  ├─ read observation（timestamp、坐标系、延迟明确）
  ├─ policy / planner / FSM 计算 action
  ├─ safety filter：限位、速度/加速度、workspace、碰撞保护
  ├─ apply action 到 articulation drive / effort 接口
  ├─ 推进 N 个 physics step
  └─ evaluate reward、termination、metrics、日志
```

动作要明确语义，不能只叫 `action`：它究竟是绝对关节角、关节增量、速度、力矩、末端 delta pose，还是夹爪开合？同一个数组不同语义会造成最隐蔽的 sim-to-real 事故。

## 3. 四种接入方式

| 方式 | 适合 | 数据/控制路径 | 面试要点 |
| --- | --- | --- | --- |
| Standalone Python | 原型、批处理、测试 | Python 直接读 wrapper、下发 action | 生命周期和 headless 管理 |
| Kit Extension | 工具面板、人工调试 | 订阅 Kit 事件，操作 Stage | 不阻塞 UI，正确 cleanup |
| OmniGraph | 可视化事件流、传感器/ROS 图 | node graph 连接数据 | 图便于观察，复杂算法仍可封装 Python/C++ node |
| ROS 2 Bridge | 真机/外部规划器联调 | topic/service/action、时间戳和 TF | QoS、时钟、坐标系、延迟与安全 |

它们可以共存，但每个控制权只能有一个 owner。例如 ROS 2 和 Python loop 同时发布同一关节命令会形成竞争；应明确 arbitration 和优先级。

## 4. 从关节控制到末端任务

```text
目标物 pose / perception
          │
          ▼
任务状态机或 planner ──> pre-grasp / grasp / lift / place
          │
          ▼
IK / trajectory generator ──> q_target(t), gripper target
          │
          ▼
Articulation drive ──> PhysX joint dynamics ──> robot state
```

`demos/02_franka_joint_control.py` 展示最后两层：向 Franka articulation 下发关节位置目标。现有 `franka_wave_demo.py` 再展示 Jacobian + DLS IK；`franka_ball_to_bowl.py` 展示 PickPlaceController 和任务状态。把这些层级说清，面试官就能判断你不是只会调用一个黑盒 controller。

## 5. 位置、速度、力矩接口的契约

```text
position target: q_des        需要 joint order、rad、limit、drive gains
velocity target: qd_des       需要 Hz、滤波、speed limit
effort/torque:   tau          需要 Nm、重力补偿、力矩限制、紧急停止
cartesian delta: dx,dR        需要 frame、IK/impedance、singularity handling
```

无论策略输出什么，都应经过 safety adapter：裁剪 joint range、限制单周期增量、限制夹爪力、检测异常速度，必要时 stop/hold。仿真训练中也要启用这些限制，否则策略会利用不真实的 drive 或穿透漏洞。

## 6. 控制器类的伪代码

```python
class PickTask:
    def reset(self, seed):
        self.scene.reset(randomize(seed))
        self.fsm.reset()
        return self.observe()

    def step(self, action):
        safe_action = self.safety.clip_and_validate(action)
        self.robot.apply_joint_position_targets(safe_action.arm)
        self.gripper.apply(safe_action.gripper)
        self.scene.step_physics(self.control_decimation)
        obs = self.observe()
        return obs, self.reward(obs), self.is_success(obs), self.is_timeout(), self.info(obs)
```

实际代码还需处理张量 batch、控制器内部状态、异常 recovery 与数据记录；伪代码的价值是明确边界和顺序。

## 7. ROS 2 接入审查

```text
Isaac Sim clock ──> /clock ──> ROS node
camera prim ──> image + camera_info ──> perception
robot state ──> joint_states / TF ──> planner
planner command ──> trajectory / joint command ──> command adapter
```

必须约定：关节名字与顺序、`base_link`/`tool0`/camera 的 TF 树、仿真时间、topic QoS、队列长度、控制频率、超时行为。真机联调还要有独立的安全节点，不能把仿真中的无限力矩或瞬时 teleport 直接映射到硬件。

## 8. 常见接入反模式

- 在算法函数里硬编码 `/World/Franka/...` 路径；
- 每帧创建/销毁对象或重复查找 Prim，造成性能抖动；
- 在 physics step 前后读错状态，观测和 action 时间错位；
- 用世界坐标下的目标喂给期望机器人基座坐标的 IK；
- 多个控制器同时写同一 dof；
- headless 训练仍每帧 render；
- reset 时忘记清 controller 的积分、滤波、FSM 状态。

# PhysX 物理仿真与数值稳定性

## 1. 物理对象的最小语义

```text
Visual mesh ── 让人/相机看见
Collider    ── 产生接触几何
Rigid body  ── 拥有质量、速度、重力，接受力与碰撞响应
Material    ── 摩擦、恢复系数等接触参数
Joint/Drive ── 约束多刚体，或驱动关节到目标
```

它们不是同一个开关。球只有 visual 不会碰撞；有 collider 但没有 rigid body 通常是静态障碍；有 rigid body 但没有 collider 也不会正确接触。对“物体为什么不掉/不碰/飞走”的排查，应按这张图逐项检查。

## 2. 接触发生了什么

```text
积分前状态 (x, v)
      │  重力、驱动力、外力
      ▼
预测新状态 ── 碰撞检测（broad phase → narrow phase）
      │
      ▼
约束求解：非穿透 + 摩擦 + joint limit + drive
      │
      ▼
积分后状态 (x_next, v_next)
```

现实接触是连续变形；实时引擎用离散时间和约束近似。因此“抓取成功”很依赖碰撞近似、时间步、质量比、夹爪闭合速度和求解器参数。不要把单次视觉上接触当作物理有效性证据。

## 3. 时间步、子步与控制频率

| 参数 | 含义 | 增大/减小的权衡 |
| --- | --- | --- |
| physics `dt` | 每次物理积分的时长 | 更小通常更稳、更慢 |
| substeps | 控制/渲染一帧内的物理细分 | 对快速接触有帮助，增加算力 |
| solver iterations | 约束迭代精度 | 接触/关节更稳，吞吐下降 |
| control decimation | 一个 action 保持的物理步数 | 提高吞吐但控制更粗糙 |

不要在出现穿透时只盲目“加摩擦”。先缩小时间步、消除初始交叠、检查 collider，再按需要调整 solver 与驱动参数。

## 4. 关节 drive 与 PD 的工程理解

许多机器人 USD 的 position drive 在概念上接近：

```text
τ ≈ Kp (q_target - q) - Kd q_dot
```

实际实现还会有最大力/速度、关节限位和求解器耦合。`Kp` 过高并不总能更精准：在接触、延迟或大质量负载下可能振荡、抖动或推穿物体。调参顺序通常是：合理单位与质量 → 平滑目标轨迹 → 限制速度/力 → 再调刚度/阻尼。

## 5. 碰撞近似选择

```text
Primitive (box/sphere/capsule)  快、稳定，适合规则物
Convex hull                     常用折中，不能表示凹洞
Convex decomposition            更像复杂物，碰撞对更多
Triangle mesh                   静态环境常用；动态物较昂贵/受限
SDF / specialized approximation 精细接触，需关注版本与开销
```

凹杯子若只用一个 convex hull，内部空腔会消失，球可能无法落入；用多块凸体或合适的凹形近似。碰撞网格要以接触任务为中心设计，而非以渲染精度为中心。

## 6. 物理参数的量级检查

以桌面操作为例，应审查而非照抄具体数值：

- 物体是否以米建模、质量是否接近真实称量；
- 重心、惯量是否合理，薄壳模型是否需要简化；
- 静摩擦不应小于动摩擦的常见物理预期；
- restitution 对抓取物体通常很低；
- 机器人关节最大速度/力矩、夹爪力和行程是否可信；
- 物体初始 pose 是否与桌面/夹爪 collider 重叠。

## 7. 稳定性故障树

```text
物体抖动 / 爆炸
├─ 尺寸或质量量级错误？                 → 检查 meters、kg、scale
├─ reset 时初始穿透？                    → 分离 collider、先静置
├─ drive 目标跳变或增益过高？            → 插值目标、限速、调 Kp/Kd
├─ dt/substep/solver 对接触不够？        → 缩 dt、增加迭代并做对照
├─ collider 不适合（薄、凹、高面数）？  → 更换近似
└─ 每帧 teleport 动态物？                → 用力/关节/约束而不是 set pose
```

## 8. “抓到”的两种实现要说清

1. **纯接触抓取**：夹爪摩擦和法向力保持物体，物理真实性高但调试困难；需验证掉落率、夹爪力和接触稳定性。
2. **任务级固定约束**：当接近和闭合条件满足时创建 fixed joint，稳定地抽象抓住；适合快速验证高层计划，但不能声称验证了真实抓取力学。

现有 `franka_ball_to_bowl.py` 使用第二种作为教学抽象。面试中主动指出抽象边界会比把它说成真实抓取更专业。

# 可展示的项目作品：从 Isaac Sim 初学者到平台候选人

## 作品目标：Mini Closed-Loop Simulation Platform

不要试图复刻完整 Waymo/CARLA 平台。做一个小而完整、可测、可讲的闭环平台，展示正确的工程边界。

```text
scenario.yaml ──> runner.py ──> simulator adapter ──> ego controller
      │                 │              │                    │
      │                 └──────> evaluator <──── state/sensors
      │                                      │
      └──────────────────────────────> run_manifest + report
```

## 阶段 A：单场景、单机器人/车辆（1–2 天）

交付：

- 一个 YAML/JSON scenario（地图/物体/初始状态/目标/seed）；
- headless runner；
- `reset()` / `step(action)`；
- 一个 controller（关节轨迹或车辆跟踪）；
- 一个成功/失败 evaluator；
- 输出 `run.json` 和终端摘要。

可复用现有 `isaacsim_interview_starter_zh/demos/04_franka_joint_target_eval.py`：将 `HOME`、`GOAL`、阈值移动到 config，输出 final error 与 seed。

## 阶段 B：批量回归和场景变体（2–4 天）

```text
scenario variants × seeds
          │
          ▼
worker pool（每个 worker 独立进程）
          │
          ▼
metrics.csv / JSONL + artifacts + summary report
```

增加：超时、失败重试、按失败原因分组、吞吐统计、固定 seed replay。此阶段最能体现平台意识。

## 阶段 C：传感器/合成数据（3–5 天）

增加一个相机或深度传感器，定义数据 schema，保存少量 RGB/depth/pose，并为每帧写 manifest。随机化物体 pose、光照或材质；检查标注、坐标、时间戳，而不只堆图片。

## 阶段 D：智驾风格扩展（选做）

- 接 CARLA 或公开模拟器，完成一个 cut-in / emergency braking scenario；
- 写 vehicle adapter，不让 evaluator 依赖具体引擎；
- 指标包含 collision、TTC、最小距离、舒适性（加速度/jerk）、路线完成率；
- 用 Docker 固化运行环境。

## 项目目录建议

```text
mini_sim_platform/
  configs/       scenario 与 controller 参数
  scenes/        USD / 地图 / 资产索引
  src/
    adapter.py   simulator 的统一接口
    runner.py    单次执行生命周期
    controller.py
    evaluator.py
    report.py
  tests/         config、metric、replay 单测
  runs/          忽略入库的 artifacts
  docs/          接口、指标、已知限制
```

## 必做指标

| 类别 | 指标 |
| --- | --- |
| 正确性 | 成功率、碰撞/越界、任务超时、replay 一致性 |
| 性能 | reset/s、step/s、每场景时长、显存/内存峰值 |
| 覆盖 | scenario 维度覆盖、seed 数、失败类别占比 |
| 可用性 | 失败日志完整率、可回放率、worker crash rate |

## 不要做的事

- 不要只录 GUI 视频，没有 config、seed、metric；
- 不要声称传感器“高保真”，却没有基准或范围说明；
- 不要在一个 Python 文件里混入调度、物理、算法、评测；
- 不要先引入 LLM/世界模型，基础闭环和回归都没有。

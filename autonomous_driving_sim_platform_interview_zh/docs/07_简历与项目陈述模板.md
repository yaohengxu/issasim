# 简历与项目陈述模板

## 项目标题示例

**可复现的 Isaac Sim 闭环仿真与评测原型**

## 真实可用的简历写法

> 基于 Isaac Sim 6.0.1 构建 Franka 机械臂仿真闭环：通过 USD reference 加载机器人资产，使用 articulation position targets 下发关节动作，读取 DOF 状态并以关节误差定义成功条件；提供 headless 运行、CLI 配置和终端指标输出。将场景、控制和评测拆分，为后续批量 scenario 与数据记录扩展预留接口。

只有在确实实现且测量后，才追加具体数字，如“固定 seed 下连续 N 次成功”或“吞吐 X step/s”。

## 不应写的内容

- “搭建了自动驾驶世界模型平台”（若只是阅读过论文）；
- “实现高保真雷达仿真”（若只调用过点云 API）；
- “百万级场景调度”（若没有真实任务、集群和指标）；
- 不注明版本、任务范围和验证方式的“熟悉/精通”。

```text
在 Isaac Sim 中，我将 USD 场景/机器人资产、articulation 控制和评测器拆开：

```

## STAR 失败案例模板

| 项 | 你应写什么 |
| --- | --- |
| Situation | 场景/版本/任务为何失败 |
| Task | 需要保证的正确性或性能目标 |
| Action | 读哪些日志、如何最小复现、修改什么接口/参数 |
| Result | 指标如何变化，仍有什么限制 |

最好的失败案例是：你没有乱调参数，而是通过 seed、日志、时钟/坐标/碰撞检查定位问题，并加上回归测试防止复发。

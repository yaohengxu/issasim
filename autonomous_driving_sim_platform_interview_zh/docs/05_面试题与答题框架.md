# 面试题与答题框架

## 系统设计

### 题：设计每天执行百万场景的仿真平台

回答结构：

1. 澄清：场景复杂度、单场景耗时、GPU/CPU 比例、是否闭环、SLA、artifact 保留期。
2. 定义 `ScenarioSpec`、`RunManifest`、`MetricEvent`、`Artifact`。
3. 控制面提交/调度/配额，执行面 worker 隔离、超时和重试。
4. 以对象存储保存大产物、数据库索引元数据，分区与生命周期降成本。
5. 用 seed + 版本 + event log 处理 replay；说明 GPU/多线程的确定性限制。
6. dashboard 展示吞吐、失败率、覆盖、成本和回归。

### 题：怎么设计确定性回放？

至少记录：scenario、seed、地图/资产 hash、仿真版本、模型版本、配置、初始状态、控制输入/事件流、dt 和平台环境。回放定义要明确：逐 bit、指标容忍区间，还是视觉/轨迹一致。多线程调度顺序、GPU 算子、浮点数和外部服务都会破坏严格确定性，因此不能夸大承诺。

## C++ / 并发

### 题：worker 如何高并发又避免资源泄漏？

- 控制面是异步队列；worker 用独立进程/容器，设置 CPU/GPU/memory limit。
- C++ 资源用 RAII，线程必须 join/cancel；GPU context/文件/共享内存要有 scope cleanup。
- heartbeat、超时、幂等任务 id、artifact 原子提交；失败可重试但限制次数。
- 先压测 reset/step/render/写盘，避免因日志或对象存储成为瓶颈。

### 题：多线程下数据竞争怎么排查？

先定义 ownership，尽量消息传递/不可变数据。共享状态以 mutex/atomic/queue 管理并明确 memory order；用 ThreadSanitizer、压力测试、trace 和固定重放缩小问题。不要用“加锁一切”作为答案，因为会损失实时性并产生死锁风险。

## 仿真与传感器

### 题：怎么评估传感器仿真保真？

按下游任务和真实对齐数据评价：camera 看投影几何、曝光/噪声、检测/分割性能；lidar 看点分布、距离误差、遮挡和反射；radar 看距离-速度-角度/RCS/虚警统计。比较条件、标定、指标和有效范围必须明确。高画质不是保真度证明。

### 题：规则场景与世界模型生成场景怎么结合？

规则场景负责可解释、可控和安全关键 corner case；生成模型提高真实分布覆盖和多样性。生成结果进入仿真前做地图/碰撞/运动学/交通规则校验，保留条件和 seed，并用规则 fallback。所有新场景通过同一 evaluator，不能因来源不同放松安全指标。

## RL / ML

### 题：RL 环境如何避免 reward hacking？

奖励与最终 safety/goal 一致，保留稀疏成功指标；监控动作、碰撞、越界、异常速度和 exploit；用未见场景/随机化评估，回放高奖励 episode。必要时加入硬约束或 safety shield，不把所有安全要求塞进 reward 权重。

## 反问问题

- 平台当前瓶颈是场景覆盖、传感器保真、执行吞吐还是回归治理？
- 被测栈如何接入，是否有稳定的 observation/action 契约？
- 什么指标会决定一次仿真平台改动是否上线？
- 真实日志、失败数据和场景库之间的回灌闭环如何运行？

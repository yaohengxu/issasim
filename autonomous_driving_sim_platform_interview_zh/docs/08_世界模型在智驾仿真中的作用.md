# 世界模型在智驾仿真中的作用

## 1. 一句话定义

在智驾语境里，**世界模型（World Model）**是学习“世界状态如何随时间和动作演化”的模型。它可以从历史观测、地图、参与者状态和控制动作中，预测未来状态、未来传感器观测或其他交通参与者行为。

```text
history: o(0:t), map, agent states, ego action a(t)
                         │
                         ▼
       world model: p(x(t+1:t+H), o(t+1:t+H) | history, a)
                         │
                         ▼
future trajectories / occupancy / video / point clouds / latent state
```

这里 `x` 是世界状态（车辆、行人、交通灯、道路上的对象等），`o` 是传感器观测（图像、点云、雷达回波等）。它不一定非要生成视频；预测可交互交通参与者轨迹的模型也可属于世界模型能力的一部分。

## 2. 它在仿真平台中扮演什么角色

世界模型是**仿真能力的增强器**，不是天然替代物理、地图、规则和评测器。

```text
                    真实驾驶日志
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
      规则/物理仿真器           学习型世界模型
      地图、车辆动力学          行为/场景/观测生成
              │                   │
              └─────── 校验与融合 ─┘
                          │
                          ▼
                 可执行 Scenario / Sensor stream
                          │
                          ▼
                 闭环 AD 系统 + 统一评测器
```

平台中主要有五类用途：

| 用途 | 世界模型做什么 | 对平台的价值 |
| --- | --- | --- |
| 行为建模 | 生成周车、行人、骑行者对 ego 的响应 | 比固定脚本更接近真实交互 |
| 场景扩增 | 基于日志条件生成天气、交通密度、事件或轨迹变体 | 提高长尾与组合覆盖 |
| 反事实推演 | 修改 ego action/初始条件，预测未来风险 | 发现日志中未发生但可能发生的危险 |
| 合成观测 | 生成或补全图像、点云、占据栅格、动态背景 | 扩大训练数据或降低渲染成本 |
| 规划辅助 | 在 latent/world state 上 roll out 多个候选 action | 为 model-based planning/RL 提供价值估计 |

## 3. 三种常见形态

```text
A. 状态/轨迹世界模型
   state + action → next state / agent trajectory / occupancy
   优点：高效、容易接 evaluator；适合行为仿真和规划。

B. 生成式传感器世界模型
   history + condition → future RGB / lidar-like observation
   优点：外观与时序多样；适合感知数据和视觉闭环。

C. Latent world model
   observation → latent z；z + action → future z / reward / termination
   优点：rollout 快；适合 RL 或模型预测控制。
```

3DGS、Diffusion、Video generation 可能构成 B 类能力；它们通常强调视觉重建/生成。不要将“能生成逼真画面”直接等同于“能预测正确交通因果”。

## 4. 标准接入链路

```text
ScenarioSpec
  ├─ map / route / lane topology
  ├─ initial agents / history window
  ├─ ego intent / candidate action
  ├─ weather / camera condition
  └─ seed + model version
            │
            ▼
      WorldModelAdapter.generate()
            │
            ▼
GeneratedCandidate
  ├─ trajectories / actors / sensor frames
  ├─ confidence / latent metadata
  └─ provenance: model, prompt/condition, seed
            │
            ▼
Validity Filter
  ├─ schema、坐标系、时间戳、速度/加速度范围
  ├─ 地图可行驶区域、碰撞、交通规则、运动学
  └─ OOD / 低置信度 / 不确定性检查
            │
            ▼
Simulator Adapter → evaluator → artifacts / metrics
```

工程上要把模型包在 `WorldModelAdapter` 后面，而不是让下游直接依赖某个 Diffusion/LLM/VLM 的私有输出。适配器应固定输入/输出 schema，记录模型 checkpoint、tokenizer/config、推理参数、随机 seed 和延迟。

## 5. 为什么必须有 validity filter

世界模型很容易“看起来合理、工程上无效”：

```text
视觉合理但几何错误：车轮/车道不连续，尺度漂移
轨迹平滑但违反交通规则：逆行、穿墙、穿越不可行驶区域
局部真实但因果错误：ego 刹车后周车/行人无响应或不合理响应
单帧好看但时序漂移：ID、光照、遮挡、地图结构不稳定
生成多样但不可控：无法复现特定 corner case
```

因此典型做法是“生成 → 约束/物理/规则校验 → 修复或拒绝 → 再执行”。对于安全关键 closed-loop 评测，低置信样本应被标记、隔离或走规则仿真 fallback，不能无声混进通过率。

## 6. 如何评测世界模型，而不是只看 demo

| 维度 | 可测指标 | 说明 |
| --- | --- | --- |
| 轨迹准确性 | ADE/FDE、速度/加速度误差、occupancy IoU | 与保留真实数据对齐 |
| 交互因果 | ego action 改变后，他车/行人的合理响应率 | 反事实测试比纯重放更重要 |
| 物理/地图有效性 | 碰撞率、越界率、违反规则率 | 生成结果的准入门槛 |
| 时序一致性 | track ID、一致的地图/物体、漂移率 | 多帧而非单帧检查 |
| 多样与覆盖 | ODD bins、稀有事件、去重率 | 不只统计生成数量 |
| 下游效用 | 感知/规划真实验证集收益、闭环安全指标 | 最终价值指标 |
| 工程质量 | p95 延迟、成本、成功率、可复现率 | 能否进入批量平台 |

## 7. 与传统仿真器的取舍

| 能力 | 规则 + 物理仿真器 | 世界模型 | 推荐组合 |
| --- | --- | --- | --- |
| 可解释/可控 | 强 | 取决于条件控制 | 规则定义骨架与安全边界 |
| 长尾真实感 | 资产/脚本成本高 | 有机会利用真实分布 | 模型生成变体，规则筛选 |
| 车辆动力学 | 强 | 常不可靠 | 仍由物理/车辆模型执行 |
| 传感器外观 | 渲染成本高、域差存在 | 可提升多样或逼真感 | 以标定和任务评测选择 |
| 反事实 | 明确但规则可能僵硬 | 灵活但因果不一定可信 | 对照/校验/不确定性估计 |
| 可复现 | seed+版本可治理 | 需严格锁定模型和采样 | 所有输出进 manifest |

## 8. 面试 60 秒答案

> 世界模型在智驾仿真中主要补足规则场景难以覆盖的真实交互和长尾分布：它可以从日志和条件生成周车行为、未来占据、传感器观测或场景变体，并支持反事实推演。它不能直接替代车辆动力学、地图约束和安全评测。平台接入时我会定义统一的 ScenarioSpec 和生成结果 schema，把模型包在 adapter 后，记录版本和 seed；生成结果必须经过坐标、时间、地图、碰撞、交通规则和不确定性过滤，最后与传统仿真场景一起走统一 evaluator。评价不只看画面，而看轨迹/交互准确、有效率、时序一致、ODD 覆盖和对真实下游指标的提升。

## 9. 初学者下一步

先不训练世界模型。先完成：场景 config → runner → evaluator → replay manifest；随后将“规则生成一个 NPC 轨迹”的函数抽象为 `WorldModelAdapter` 接口。只有这条平台链路稳定后，再将真实模型输出接入，才能判断模型是否真的给仿真带来价值。
